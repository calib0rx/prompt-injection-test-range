Threat Modeling for AI-Integrated Systems

Security Architecture · March 2026

Traditional threat modeling frameworks like STRIDE and PASTA were designed for deterministic software systems. AI-integrated systems introduce a new category of threats that these frameworks do not adequately address: adversarial manipulation of model inputs, outputs, and decision boundaries.

AI-Specific Threat Categories

Model poisoning attacks target the training pipeline. Data exfiltration attacks target the inference pipeline. Prompt injection attacks target the integration layer between the model and its host application. Each category requires different threat modeling approaches and different mitigation strategies.

Trust Boundaries in AI Systems

The most important trust boundary in an AI-integrated system is between the model and its tools. When a language model can invoke external tools — APIs, databases, file systems — the model becomes a potential proxy for attackers. Every tool invocation should be treated as a cross-trust-boundary operation, subject to validation, authorization, and audit logging.

The second critical trust boundary is between user input and model context. In retrieval-augmented generation systems, documents retrieved from external sources enter the model's context alongside system instructions and user queries. Without clear delineation of trust levels, the model cannot distinguish between authoritative instructions and potentially adversarial content.
