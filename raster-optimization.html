Raster Data Optimization for Cloud-Native Workflows

Geodata Field Notes · January 2026

Cloud-optimized GeoTIFF (COG) has become the standard raster format for cloud-native geospatial workflows. A COG is a regular GeoTIFF with internal tiling, overviews, and a specific byte layout that enables efficient HTTP range request access. This means a client can read a small spatial extent from a multi-gigabyte raster without downloading the entire file.

Creating COGs

GDAL's gdal_translate with the COG driver is the standard conversion path. Key options include COMPRESS (DEFLATE for lossless, JPEG for imagery), BLOCKSIZE (512 is typical), and OVERVIEW_RESAMPLING (AVERAGE for continuous data, NEAREST for categorical). The COPY_SRC_OVERVIEWS option preserves existing overviews; without it, overviews are regenerated, which can be slow for large files. Always validate the result with gdalinfo --checksum to confirm data integrity after conversion.

STAC Catalogs

The SpatioTemporal Asset Catalog (STAC) specification provides a standard way to describe collections of geospatial assets — satellite imagery, DEM tiles, land cover classifications — with consistent metadata. A STAC catalog is a set of JSON files that describe Items (individual assets with geometry and temporal extent), Collections (groups of related items), and Catalogs (top-level entry points). STAC APIs add search capabilities with spatial, temporal, and property-based filters.
